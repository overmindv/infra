# Локальный agent harness

Harness даёт агенту короткий контекст и воспроизводимый список проверок выбранного
репозитория. Нужен Python 3.9+ на macOS/Linux; внешних Python-зависимостей нет.
Источником команд служит [agent-services.json](../agent-services.json).
Общие правила работы находятся в [docs/harness](../../docs/harness/README.md).

## Команды

Из `infra`:

```bash
make agent-context                      # ветка, число изменений, инструкции и команды
make agent-context SERVICE=frontend     # контекст только выбранного репозитория
make agent-check                        # проверить доступную часть workspace
make agent-check STRICT=1               # отсутствующие соседи считаются ошибкой
make agent-verify SERVICE=content DRY_RUN=1
make agent-verify SERVICE=content TIMEOUT=300
make agent-harness-test
```

Скрипт работает из любого текущего каталога; расположение workspace определяется
по самому скрипту, а не по `pwd`. Клон `infra` может иметь другое имя.

```bash
python3 /path/to/infra/scripts/agent_harness.py context --service tasks
python3 /path/to/infra/scripts/agent_harness.py check --strict-workspace
python3 /path/to/infra/scripts/agent_harness.py verify --service frontend --dry-run
```

`context` не читает содержимое `.env`, diff, тела запросов или журналы. Он показывает
только название ветки и число изменённых записей Git, без имён изменённых файлов.
Контекст не является результатом проверки качества кода.

`check` проверяет структуру manifest, наличие указанных инструкций, общих документов
и деклараций команд в Makefile/package.json. Он не исполняет Makefile, не проверяет
установленные инструменты и не требует, чтобы новые файлы уже были закоммичены.
Отдельный клон infra поддерживается: отсутствующие соседи выводятся как `MISSING`,
итог — `PARTIAL`, код возврата 0. `--strict-workspace` делает отсутствие ошибкой.
Явно выбранный через `--service` отсутствующий репозиторий всегда является ошибкой.
Существующий репозиторий с отсутствующим обязательным файлом также даёт ошибку.
`--service` ограничивает проверку выбранным репозиторием и общими ссылками;
для проверки наличия всех 13 репозиториев используйте `--strict-workspace` без фильтра.

`verify` требует `--service`, сначала выполняет `check` выбранного репозитория,
затем последовательно запускает его команды. Полный список cwd/argv виден заранее.
`--dry-run` проверяет файлы и печатает план, но не запускает команды и не проверяет
наличие инструментов. Для обычного запуска зависимости должны быть установлены
заранее; отсутствующий `bin/golangci-lint` останавливает выполнение до `make lint`,
чтобы Makefile не установил его автоматически. `content` не имеет lint-цели,
а `tests` использует немодифицирующую `lint-check`.

Harness не запускает установки, миграции, очистки, reset, Docker startup или
component-тесты. Обычные проверки могут создавать штатные артефакты
(coverage, dist, бинарники), а Go/npm используют свои стандартные кэши.
Вывод запущенных проверок передаётся напрямую; правила обезличивания логов
должны соблюдать сами сервисы. `tests` выполняет e2e через gateway и требует
заранее поднятый стек; `infra lint` требует Docker CLI с Compose.

Таймаут применяется к каждой команде отдельно: по умолчанию 300 секунд,
допустимый диапазон 1–3600. По таймауту останавливается вся группа процессов,
возвращается 124. Ошибка команды сохраняет её exit code и прерывает последующие
проверки; Ctrl-C возвращает 130. Ошибка manifest/CLI возвращает 2, ошибка
структурной проверки — 1. `make` может обернуть ненулевой код своим кодом 2;
точный код дочерней команды сохраняется при прямом запуске Python CLI.

`sandbox` намеренно исключён: harness не проверяет и не меняет внешний исполнитель.
Обновляя контракт команд или расположение инструкций, обновите manifest и запустите
`make agent-harness-test`, `make agent-check STRICT=1` и dry-run затронутого сервиса.
